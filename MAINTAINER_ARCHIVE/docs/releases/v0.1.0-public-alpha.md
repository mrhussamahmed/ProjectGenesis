# ProjectGenesis v0.1.0 Public Alpha

Suggested tag: `v0.1.0-public-alpha`

## Short Description

ProjectGenesis is a Markdown-first scaffold for AI-assisted software delivery.
It helps agents turn rough product input into evidence-linked project context,
requirements, specs, backlog candidates, ADRs, validation plans, reviews, and
handoffs.

## Included

- Public README and AGPLv3 license.
- Shared agent rules for Codex, Claude, and generic AI agents.
- Role files for product discovery, spec creation, architecture, backlog,
  implementation, QA, security, release, documentation, PR review, and diagrams.
- Source-of-truth governance, artifact registry, traceability matrix, current
  state, handoff, stale-item, and worklog patterns.
- Canonical intake folders, requirements registers, context packs, command
  prompt framework, and `Start requirement breakdown` workflow.
- Bootstrap validation scripts and GitHub Actions validation workflow.
- GitHub repository setup guidance, public launch checklist, demo script,
  illustrative example, social drafts, issue templates, and seed issue drafts.

## Who It Is For

- Solo builders and founders using AI agents for early product planning.
- Engineering teams that want AI-generated planning artifacts to stay
  reviewable and traceable.
- Maintainers who prefer repository files over chat memory as project truth.

## What It Is Not

- It is not an app generator.
- It is not a replacement for product, engineering, security, or legal review.
- It does not select a stack, database, hosting provider, or ticket tracker.
- It does not enforce GitHub repository settings by itself.

## Known Limitations

- The process can feel heavy for very small experiments.
- Agents must actually read and follow the repository rules.
- Public examples are illustrative unless a live recording says otherwise.
- GitHub topics, template settings, releases, labels, and issues require manual
  GitHub UI or authenticated CLI work.
- External tracker integration is optional and not preconfigured.

## Validation Before Release

- Run `bash SCRIPTS/validate-bootstrap.sh`.
- Run `bash SCRIPTS/validate-bootstrap-red-checks.sh`.
- Run `git diff --check`.
- Confirm GitHub Actions `validate` passes on the release commit.
- Confirm `README.md`, `docs/public_launch_checklist.md`, and the demo/example
  files match the release contents.

## Manual GitHub Release Steps

1. Open GitHub Releases.
2. Draft a new release.
3. Create or select tag `v0.1.0-public-alpha`.
4. Use `main` as the target branch.
5. Paste this release draft and trim only details that no longer match the
   repository.
6. Mark as pre-release if alpha status should be visually explicit.
7. Publish only after validation and review requirements are satisfied.
