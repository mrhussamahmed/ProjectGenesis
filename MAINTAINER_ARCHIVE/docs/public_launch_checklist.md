# Public Launch Checklist

Use this checklist when preparing ProjectGenesis for public discovery. It does
not replace `GITHUB_REPOSITORY_SETUP.md`, `RELEASE_READINESS.md`, or the
governance files.

## GitHub About

Suggested description:

```text
AI-native software delivery scaffold that turns messy ideas into evidence-linked requirements, specs, backlog, ADRs, tests, reviews, and handoffs.
```

Recommended topics, maximum 20:

- `ai-agents`
- `ai-coding`
- `codex`
- `claude-code`
- `software-engineering`
- `spec-driven-development`
- `requirements-engineering`
- `product-management`
- `adr`
- `backlog`
- `developer-tools`
- `markdown`
- `vibe-coding`
- `agentic-workflows`
- `governance`
- `tdd`
- `open-source`
- `repo-template`
- `ai-workflows`
- `project-scaffold`

Manual GitHub UI steps:

1. Open the repository on GitHub.
2. Select the gear icon beside the About panel.
3. Set the description to the text above.
4. Add the recommended topics.
5. Add the project website only if a real public URL exists.

## Template Repository

- In GitHub, open Settings.
- In General, enable Template repository.
- Confirm the repository still uses the intended default branch.
- Do not change branch protection while enabling template use.

## Release Creation

- Confirm `main` is current and validation passes.
- Review `docs/releases/v0.1.0-public-alpha.md`.
- Create tag `v0.1.0-public-alpha`.
- Use the release notes draft as the GitHub release body.
- Mark it as a pre-release if the maintainer wants explicit alpha signaling.
- Do not claim package-manager availability unless it exists.

## Issue Creation

- Confirm `.github/ISSUE_TEMPLATE/` appears on `main`.
- Create seed issues from `docs/launch/seed-github-issues.md`.
- Apply labels manually if labels are not already configured.
- Do not claim seed issues exist until GitHub returns real issue URLs.

## Demo Video

- Use `docs/demo/60-second-demo-script.md`.
- Show the README, raw input, expected illustrative outputs, and validation.
- Keep the recording short and readable.
- Do not imply the example outputs were generated by a live agent unless that
  recording actually shows the live run.

## Social Launch

- Use `docs/launch/social-posts.md` as draft copy.
- Link to the repository and the example demo.
- Be explicit that ProjectGenesis is a Markdown-first scaffold, not an app
  generator.
- Avoid unverifiable adoption or performance claims.

## Post-Launch Feedback

- Watch incoming issues for unclear setup, missing examples, or governance
  friction.
- Convert recurring questions into documentation improvements.
- Keep public claims aligned with repository artifacts.
- Prioritize examples and setup clarity before adding new mechanics.
- Record accepted follow-up work as issues, backlog items, or specs before
  implementation.
